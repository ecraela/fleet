# Standalone console

A React and React Aria console built and served by the Go manager. Local login
and the operator API work without Converge. See the
[self-hosted console guide](../docs/self-hosted-console.md).

`src/haproxy*` and `ui/` originated in the Ecraela Converge console and design
system snapshot of 2026-10-27, following ADR 0048. This repository owns its copy,
including local authentication and provider-neutral DNS instructions. The UI
subset contains only components needed by this console; it has no Converge
checkout, workspace, identity-service or telemetry dependency. All package
requirements are public and pinned in `pnpm-lock.yaml`.

`@ecraela/ui` resolves to `ui/`. See the [component guide](ui/README.md) for
styling and accessibility conventions. Record changes shared with Converge
explicitly; neither frontend consumes the other's working tree at runtime.
The original frontend and included Ecraela UI source use
[AGPL-3.0-only](../LICENSE), with [optional commercial licensing and paid support](../LICENSING.md).
Third-party components retain their own licenses.

The login page, account menu and footer link to `/legal/`. Build-time legal files
are generated by `scripts/legal.py` and embedded with the console. They provide
the matching project source, AGPL text and original dependency notices without
requiring GitHub access. `make legal-update` is an explicit review step after
adding source or changing dependencies; ordinary builds fail on a stale inventory.

ADR [0052](../docs/adr/0052-haproxy-console-navigation.md) defines the shared
Overview, Applications, Infrastructure, Activity and Settings structure. The
2026-10-28 navigation update is mirrored in Converge with its existing MFA and
DNS adapters. The PageTabs, Breadcrumbs and Link components were synchronized
from the design system for this update. Resource routes use React Router; the
authenticated HAProxy client and its bounded caches survive section changes.

## Development

From the repository root:

```sh
make web-install
make web-check web-test web-build
```

`make web-build` writes the assets embedded by the Go manager into
`internal/webui/dist/`. Generated assets are excluded from Git.
`make build` builds both the frontend and the Go executables.

For hot reload, run `pnpm --dir web dev` against a manager configured for local
login on `http://localhost:5180`. The Vite proxy targets
`https://localhost:18445` by default; set `HAPROXY_DEV_MANAGER_URL` to change the
loopback HTTPS endpoint. Its development-only upstream skips certificate
verification for the local test CA. Production serves assets from Go and does
not use Vite or that proxy.

Node setup diagnostics use the optional `setup` field on the existing discovery
API (ADR 0051), also used by the Converge console. Keep this contract compatible
with agents that do not report diagnostics.

The client-IP/Geo setup drawer and its validation/evidence model are mirrored in
Converge (`haproxy-geo-setup*`), following ADR 0057. Both use the existing read APIs;
proxy trust and dataset files remain host-owned. Keep the two copies consistent
when changing generated profiles or readiness checks.

The Traffic rules page, editing/setup drawers and typed request-decision model
are mirrored in Converge (`haproxy-traffic-*`, ADR 0058). Both use the same
application deployment/version APIs and exact-spec read-only counts. Standalone
keeps local login; Converge retains its own login and DNS review adapters.

## Feedback and refreshes

HAProxy sections use the shared `Section` stack layout to separate notices,
fields and tables. Bounded local collections use `PaginatedDataTable`: ten rows
initially, with page-size choices for longer lists. Remote request searches keep
their server cursors. Background refreshes preserve loaded content and the
selected page; initial loading indicators wait one second to avoid flashing.

Request and Geo navigation caches belong to the authenticated client, retain at
most twelve queries per resource type and clear when that client is disposed.
Cached observations keep their collection time and cannot authorize writes.
Application validation is shared between both consoles; feedback appears after
submission and focuses the first invalid field.

Standalone uses the design system's account menu and avatar, with local account
actions and appearance controls. Only the theme preference uses browser storage;
authentication remains in HTTP-only cookies. The account, section, loading and
table components are synchronized with Converge's UI package.

## Analytics presentation

Overview, node metrics, application traffic and geography use the shared metric
cards and chart panels. Sparkline values come from recorded time buckets, while
card labels distinguish live observations from range totals. Cluster sparklines
require observations from every displayed node; missing data is never zero-filled.
HTTP response plots use stacked rates with the existing response-class colors.
No comparison-period deltas are shown without comparison data. The data palette,
metric cards and chart geometry are mirrored from Converge’s UI package, with no
Converge runtime dependency.

The topology reads from top to bottom without connector lines. Up to four nodes
use cards; larger supplied groups use a searchable, status-filtered table with
pagination. The 64-node Storybook fixture exercises layout behavior only: current
managed topology, maintenance and application rollout APIs still accept at most
twelve nodes per cluster. Raising that operational limit needs separate backend
capacity and failure testing.

## Cluster navigation

The landing page lists clusters with health, reporting-node counts and recorded
15-minute traffic sparklines. Search and pagination keep chart queries limited
to the visible ten rows, with up to twelve active nodes per cluster and four
history requests in flight. Incomplete inventory and missing observations stay
explicit; they never become healthy status or zero traffic.

Open a cluster to scope its five sections. The Clusters breadcrumb returns to the
list and preserves its search and page. Existing node and application URLs select
the resource’s owning cluster, even if the query contains another cluster.
Installation settings and local login remain available without selecting a cluster.
The navigation and compact Sparkline component are mirrored in Converge.
