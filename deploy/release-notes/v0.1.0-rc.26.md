Fleet v0.1.0-rc.26 fixes signed native updater packaging so every managed activation retains the complete authenticated installer bundle. Request-history pagination now uses the same ID ordering for log-store sorting and cursor filtering, including records with tied timestamps. The release also includes corrected Fleet chart spacing, an independent direnv/Nix development environment and stronger native upgrade/rollback qualification.

Start from rc.25. Before the first native managed update, authenticate the candidate host tool and stage the complete signed rc.26 target bundle on each affected native host with its existing profile and publisher. Preserve a complete authenticated rc.25 rollback bundle. Staging a target does not replace an installed rc.25 updater; inspect any existing incomplete cache, pending operation or needs-attention result before continuing. Never clear identity, journals or pending markers to force a retry.

Qualify agent upgrade, rollback and re-upgrade while the manager still runs rc.25, then restore the baseline agents before qualifying the manager transition. The reviewed candidate compatibility range is restricted to rc.25 through rc.26. Rc.25's immutable signed bounds do not admit rc.26 peers for an older-target managed activation. After upgrading the whole installation to rc.26, a managed downgrade of individual components to rc.25 is therefore not a qualified rollback path. Retain a verified, fenced full-installation recovery checkpoint and its original identities; do not override peer checks or widen signed bounds.

Manager and ingestion activation briefly interrupts management sessions. HAProxy continues serving its loaded configuration. A control disconnect during a change remains fail-closed and may pause the update or trigger a verified rollback. Inspect the recorded terminal outcome and fresh health before planning a new request. Control-session diagnostics now record status codes and duration without raw transport messages, credentials or keys.

This is a release candidate. Published-assets qualification on Ubuntu 24.04 amd64 and arm64, standalone and linked installation witnesses, recovery and a new 48-hour soak of this exact installed release are required before production sign-off. An older release's soak does not qualify rc.26.
