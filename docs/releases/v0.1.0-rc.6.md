# Private release candidate: v0.1.0-rc.6

This candidate includes existing-node setup diagnostics, dedicated console
sections and the bounded live-observation store. GitHub source, release assets
and GHCR distribution remain private. No source license is selected.

## Changes

- Standalone Overview, Applications, Infrastructure, Activity and Settings,
  with resource detail pages, preserved live chart state and editing drawers.
- Read-only setup diagnostics for existing HAProxy instances before granting
  runtime or persistent-configuration permissions.
- Latest two validated summaries per node for the live feed, independently of
  VictoriaMetrics history buffering. Tenant, session, cardinality and freshness
  limits remain enforced; historical delivery is still acknowledged separately.
- Isolated PostgreSQL test runners, current frontend dependencies, and stronger
  recovery checks for exact images and healthy restored backends.
- Explicit support for the additive database schema-19-to-20 upgrade with
  software rollback to rc.5 and unchanged storage image pins.

Converge's separate API includes the Bandit dependency and notifier/startup fixes.
It is optional and is not included in this product image or native executables.

## Install, upgrade and rollback

Use the [self-hosted installation guide](../self-hosted-installation.md).
Supported pilot: Ubuntu 24.04, Linux amd64/arm64, local Docker Engine/Compose,
Python 3.11+, Cosign 3+, OpenSSL and age 1.2+. Start the manager on a dedicated
2-CPU, 4-GiB host with at least 20 GiB free disk. Workload capacity must be measured
for the intended deployment. Agents need access to their customer-owned nodes;
enrollment does not create HAProxy processes or an upstream traffic entrypoint.

Authenticate the exact manifest and installer checksums before execution. The
manifest binds Linux executables, the embedded console, host tools, signed
storage profile and multi-platform GHCR digest. Publisher identity is the
repository's release workflow at this exact tag. Public Sigstore records expose
the workflow identity and artifact digests, not source or runtime credentials.

Use the rc.6 installer to upgrade an rc.5 installation or roll its software back.
The older installer cannot manage schema 20. The new observation table remains
present during rollback; identities, configuration, audit and TLS state are never
rewound. See [ADR 0054](../adr/0054-haproxy-additive-observation-upgrade.md).
Other schema/storage transitions remain unsupported.

## Qualification

The normal CI verifies source, existing-node onboarding, Linux/Docker agent
lifecycle and signed-fixture self-hosted recovery. The release workflow reruns
checks with a dedicated PostgreSQL 18 database before publishing exact signed
GitHub/GHCR artifacts.

After publication, qualify the actual assets on a clean Ubuntu 24.04 runner:

```sh
gh workflow run release-qualification.yml --repo ecraela/haproxy-manager \
  -f baseline=v0.1.0-rc.5 -f candidate=v0.1.0-rc.6
```

This installs rc.6 directly into fresh storage with HTTPS local login. It then
separately installs rc.5, enrolls two real HAProxy nodes, upgrades to rc.6,
rolls back to rc.5 and upgrades again while two applications serve HTTP/HTTPS.
The evidence records schema 19 initially and schema 20 across software rollback.
Encrypted cold restore verifies saved identities, node keys, TLS, history and
fresh observations. Only sanitized results are retained.

Check the Actions result for this exact source/tag before deploying. These tests
qualify a single-host pilot. The Hetzner trial must still measure real networking,
hardware resources and independent-host failure. Teams/local MFA, manager HA,
arbitrary storage migrations and managed off-host backup retention remain deferred.

HAProxy changes require permissions, local agent policy, verification and audit;
they have no approval workflow. Converge DNS retains its normal review flow.
