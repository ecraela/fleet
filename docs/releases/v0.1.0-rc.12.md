# Private release candidate: v0.1.0-rc.12

This candidate fixes three security findings in raw configuration rollback,
fleet telemetry and shared maintenance admission.

Rollback now requires a private node-local binding between the retained raw
snapshot and its independently observed settings. Current TLS paths and grants,
request-log permission and compiled traffic-policy dependencies are checked before validation
and again before commit. Typed settings cannot disguise a different raw snapshot.
Authorized full-file rollback, DPA normalization and read-only receipt recovery
keep their existing behavior.

**Upgrade limitation:** older raw snapshots without observation bindings remain
on disk but cannot be restored by rc.12. The current configuration receives a
binding on its first complete observation after upgrade, and new edits retain
bound rollback bases. Back up the entire private agent state, including
`configuration-bindings/`; manager history alone cannot recreate it. Do not
re-enroll nodes or discard history to work around a missing binding.

Ingestion rejects invalid or label-distinct agent status singletons before
publishing live observations or writing historical data. Historical fleet reads
reduce old duplicate-series cardinality in storage and isolate malformed status
to the responsible node. Healthy peers remain visible to fleet and incident
evaluation. Foreign-scope storage responses still fail closed as a whole.

Rollouts and runnable maintenance share a limit of 16 per installation and eight
per organization, including resumed operations. Held and recovery-attention
maintenance preserve their safety fences without consuming runnable capacity;
their scheduling checkpoints rotate. An organization may retain up to 16
nonterminal maintenance reservations before starting another withdrawal.

Regression coverage includes malicious rollback intent and certificate alias
changes, valid full/TLS rollback and normalized receipt recovery, ingestion and
historical poisoning, real VictoriaMetrics legacy cardinality, and concurrent
memory/PostgreSQL admission. The release workflows run the storage regression
against an isolated VictoriaMetrics service.

The rolling recovery drill holds its real streaming probes until it observes
drainage, so slow manager startup cannot finish the probe before the assertion.
Reloading while a probe is active still fails the drill.
Entrypoint restart checks require new configuration/runtime observations and a
healthy peer before asserting traffic isolation; lost withdrawal still fails.
Rejoin probes wait for saved configuration and completed backend health checks,
and refresh rejected stale fences within a bounded retry. The `maintenance`
acceptance mode repeats this restart scenario on its own isolated pair.

The build remains on Go 1.26.10. Runtime protocol, database schema, node identities,
local login, ACME accounts and serving keys are unchanged. Upgrade management
services before agents, preserving their persistent state. No host upgrade is
implied by publishing this candidate. The repository and release image remain
private. Source licensing was undecided when this candidate was published. The
subsequent [licensing decision](../../LICENSING.md) applies to source carrying the
new notices; this release's tags and artifacts have not been rewritten.
