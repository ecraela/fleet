# Private release candidate: v0.1.0-rc.5

This candidate adds standalone self-hosted operation to the existing HAProxy
manager and agent. Distribution remains private; no source license is selected.

## Included

- Embedded console, administrator/viewer local login and host-owned account
  provisioning/recovery. Converge is optional.
- Outbound Converge connector with local observe/manage consent, independent
  local login and revocation. No inbound manager API port is required for linking.
- Signed exact Linux amd64/arm64 executables and a multi-platform GHCR image,
  plus authenticated Linux/Docker installers and pinned storage profiles.
- Compatible manager upgrades, retained previous-release rollback, encrypted
  signed manager/node backups and fenced cold restore preserving identities,
  keys, history and configuration.

## Supported pilot shape

Ubuntu 24.04, local Docker Engine/Compose, Python 3.11+, Cosign 3+, OpenSSL and
age 1.2+. Begin with a dedicated 2-CPU, 4-GiB host and 20 GiB free persistent disk.
These are installation requirements, not measured production capacity limits.
Customer-owned HAProxy nodes and networking remain outside the management plane.

The connector pilot supports one manager per Converge organization and one relay
replica. Teams, local MFA, native manager/systemd packaging, storage/schema
migrations, multi-host management availability and automated off-host backup
transfer/retention are deferred.

HAProxy changes require permissions, local node policies and verification, with
history/audit and rollback. They have no review or approval workflow. Converge
DNS changes retain their normal review workflow.

## Install and recovery

Use the [installation runbook](../self-hosted-installation.md). Authenticate the
exact manifest against the release workflow's Sigstore identity before checking
installer checksums or executing either installer. Authenticate the GHCR image
against the same workflow and exact tag. Private GitHub asset downloads and GHCR
pulls need separate host authentication. Signing exposes artifact digests and
workflow identity in Sigstore's public transparency service, not repository
contents or runtime state.

The first self-hosted storage profile is database schema 19. Earlier rc.3 agent
releases have no standalone installer. This release does not offer an in-place
upgrade of an earlier custom management stack. Existing node identity directories
must be preserved; never re-enroll nodes as a recovery shortcut.

## Repeatable qualification

The `Published private release qualification` workflow downloads actual private
GitHub release assets, verifies every manifest/file and GHCR signature, then
installs into fresh volumes on a clean Ubuntu 24.04 runner. It requires no
Converge, source build, fixture images or custom release signer.

For this first installer release, rc.4 supplies an independently signed baseline
with the same schema/storage contract; rc.5 is the candidate. Both tags use the
same source snapshot with distinct embedded versions. This tests the software
lifecycle, not a database migration or a behavior change between revisions.

The scenario creates two real HAProxy nodes, uses local HTTPS login and secure
cookies, continuously exercises two HTTP/HTTPS applications, upgrades to rc.5,
rolls back to rc.4 and upgrades again. It then checkpoints rc.5, refuses activation
while the source runs and restores into fresh storage. It requires the original
identities/keys, historical metrics, fresh restored observations and actual TLS
serving from recovered node files. Only sanitized measurements are retained as a
GitHub Actions artifact. Failed-start automatic rollback remains covered by the
separate signed-fixture lifecycle job; broken binaries are never published.

Run the published-assets scenario with:

```sh
gh workflow run release-qualification.yml --repo ecraela/haproxy-manager \
  -f baseline=v0.1.0-rc.4 -f candidate=v0.1.0-rc.5
```

Passing these scenarios qualifies a single-host pilot. Longer hardware-specific
soaks, broader operating-system qualification and multi-host management failover
remain separate release criteria.
