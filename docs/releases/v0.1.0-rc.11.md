# Private release candidate: v0.1.0-rc.11

This candidate fixes a cold-restore startup race and includes the standalone
console navigation and interaction updates, trusted client IP setup, and
application traffic rules developed after rc.9.

Fresh-storage recovery now waits for PostgreSQL's final TCP listener. The image's
temporary initialization server can answer a Unix-socket readiness probe before
the target database exists. Restores from older checkpoints replace that probe
too. Checkpoints also retain the active traffic-collection Compose overlay.
Database errors still omit credentials and private backup contents from logs.
The Geo smoke check runs as the demo agent UID/GID, keeping policy and database
files private on Linux.

The build uses Go 1.26.10, including the current HTTP/TLS and certificate trust
fixes, and golang.org/x/net 0.62.0. Source CI and release publication check
reachable Go vulnerabilities in addition to frontend dependency advisories. The local-login rate-limit test uses
an explicit minute boundary rather than depending on the wall clock.

The standalone console groups work into Overview, Applications, Infrastructure,
Activity and Settings. Cluster rows include traffic history; application and node
details keep editing in drawers. HTTPS settings use a draft toggle and one deploy
action. Automatic TLS presents the action appropriate to its current state.
Maintenance asks for confirmation before withdrawal or rejoin. Request tables use
standard pagination, and charts keep labels and values separate in tooltips.
Country distribution includes a globe and count/rate rankings without an external
map service. Unknown locations remain unknown.

Traffic rules support ordered IP/CIDR, country and ASN matches, observe mode,
enforcement and app-scoped rollback. Guided client-address setup explains direct
peers, trusted forwarded headers and PROXY protocol. Addresses are evaluated on
the node; request records continue to omit raw client IPs.

Automatic TLS can recover an issuer account removed by a restarted private test
CA using the existing account key. Transient issuer failures continue retrying
with bounded backoff; issuer rate-limit delays remain respected. Certificate
activation still waits for verified node health and completion of maintenance.

Upgrade the manager, ingestion service and optional Converge relay before agents.
The transport protocol, identity state schema and database migrations are unchanged
from rc.9. Application control now advertises version 6 for traffic rules. Remove
those policies with rc.11 before a software rollback to rc.9; older managers
cannot interpret that intent. Never leave an older manager writing the same
database. Keep the authenticated host tools when rolling a compatible runtime back.
Persistent node identities, installation credentials, ACME accounts and serving
keys remain in place; upgrades do not enroll nodes again.

The supported pilot remains Ubuntu 24.04 with Docker, plus Linux/systemd agents.
HAProxy writes require permissions and local policy, without approvals. DNS keeps
its normal review flow. The repository and release image remain private; this
candidate does not choose a source license.
